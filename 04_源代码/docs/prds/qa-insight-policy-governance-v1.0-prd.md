# 问答洞察与制度治理闭环 - 产品需求文档（PRD）

## 需求描述

### 背景

- **业务问题：** 现有问答洞察和制度漏洞扫描能够发现信号，但缺少从异常下钻、去重建项、治理处理到原问题验证的连续路径。
- **目标用户：** 负责制度维护、知识库质量与员工意见处理的 HR 管理员。
- **价值主张：** 在不重复建设扫描、反馈和回归能力的前提下，形成“问答质量监控 → 问题发现 → AI 诊断 → 制度治理 → 回归验证”的闭环。

### 功能边界

- 保留并复用 `QueryLog`、`Feedback`、`PolicyGapScan/Issue`、`RegressionCase`、混合检索和索引发布能力。
- 不生成虚假业务数据；历史指标仅来自实际日志。
- 不展示模型隐藏推理过程，只展示可验证的检索、制度和反馈依据。
- 不另建一套孤立的“制度问题”数据；在现有 `PolicyGapIssue` 上增加最小治理字段。

## 复用审计与设计决策

| 能力 | 当前状态 | 决策 |
|---|---|---|
| 查询量、命中率、拒答率、澄清率、耗时 | `analytics_summary` 已聚合 | 扩展按日质量序列、周期对比和问题诊断，不重写 |
| 热门/未命中问题 | 已有问题与次数 | 扩展状态、分数、耗时、制度、最近时间和原因分类 |
| 员工反馈 | 已有快照、分类、处理时间线 | 作为问题来源和诊断依据直接复用 |
| AI 制度扫描 | 已有定时/手动扫描及规则降级 | 保留扫描入口，扫描结果去重汇入制度问题中心 |
| 回归验证 | 已有反馈复测和回归用例 | 制度问题重新验证复用同一 Top 5 混合检索 |
| 制度问题状态 | 当前缺失 | 在 `PolicyGapIssue` 增加待核验/处理中/已解决、备注和复测结果 |

## 详细需求

### 问答数据洞察

- 四张指标卡显示真实指标、上一周期趋势、Sparkline；可信命中率显示回答状态环形构成。
- 趋势图使用 ECharts，支持最近 7 天、30 天和自定义时间，展示后端实际存在的查询量、命中率、澄清率、拒答率和平均耗时。
- 热门问题支持热度条和 Drawer 下钻；诊断仅展示日志中实际存在的状态、检索质量、制度命中、耗时、反馈与最近回答摘要。
- 未命中问题显示原因、次数、最近时间，并可去重创建制度问题。
- 反馈分类转换为中文比例条，点击可查看对应反馈。
- 全局筛选联动指标、趋势和问题列表；各接口独立容错。

### 制度问题中心

- 汇总 AI 扫描、问答发现、员工反馈、人工录入来源，同一去重键只保留一个问题并追加来源与证据。
- 支持来源、风险和状态筛选；卡片展示风险、类型、来源、信号、建议和状态。
- Drawer 展示基本信息、依据、相关制度、建议动作、处理备注和最近复测。
- 状态流为 `pending → processing → resolved`；未通过重新验证时不得标记已解决。
- AI 扫描保留原入口，并展示真实扫描步骤说明和扫描结果摘要。

## API 与数据最小扩展

- 扩展 `GET /api/v1/admin/analytics` 返回 `daily_quality`、`period_comparison` 和增强问题列表。
- 新增 `GET/POST /api/v1/admin/policy-issues`。
- 新增 `PATCH /api/v1/admin/policy-issues/{id}`。
- 新增 `POST /api/v1/admin/policy-issues/{id}/retest`。
- `PolicyGapIssue` 增加 `dedupe_key`、`sources`、`status`、`origin_question`、`processing_note`、`last_seen_at`、`resolved_at`、`last_retest`。

## 验收标准

- [ ] 指标和趋势完全来自实际 QueryLog/Feedback，不硬编码业务数据。
- [ ] 热门和未命中问题可下钻，未命中可一键创建且不会重复。
- [ ] 新问题立即出现在制度问题中心并标记“问答发现”。
- [ ] 后续 AI 扫描命中同一问题时合并来源和证据。
- [ ] HR 可开始处理、备注、重新验证；验证通过后可标记已解决。
- [ ] 单个治理接口失败不清空其他 Dashboard 数据。
- [ ] Pytest、Vitest、TypeScript strict、生产构建与响应式检查通过。
