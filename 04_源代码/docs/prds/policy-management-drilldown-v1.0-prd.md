# 制度管理轻量下钻 - 产品需求文档（PRD）

## 需求描述

### 背景

- **业务问题：** HR 制度管理已有完整数据，但统计卡、制度名称、版本号、条款数和状态大多只能阅读，缺少连续下钻。
- **目标用户：** 负责制度维护、索引发布和问答治理的 HR 管理员。
- **价值主张：** 不改变页面骨架，通过点击现有信息形成“总览 → 制度 → 版本 → 条款 → 问答引用”的探索链路。

### 功能边界

- 保留现有布局、色彩、索引发布、Top 5、新增版本、启停、预览和删除逻辑。
- 复用现有制度 Reader、版本列表和索引状态。
- 新增一个管理员只读条款引用聚合接口，数据来自 `ClaimEvidence/Claim/Answer`。
- 不新增数据库表，不伪造引用次数或排名，不改变 Top 5 业务含义。

## 设计决策

### 交互方案

- 四张统计卡增加键盘可访问的点击行为和轻量 Hover。
- 制度列表增加分类筛选；制度名、版本号、条款数和状态成为语义化按钮。
- 详情统一使用一个 Drawer，通过“概览 / 版本历史 / 条款目录 / 条款详情”逐步披露。
- 高频“预览”保留，低频启停和删除收进原生管理菜单；删除继续调用原确认流程。
- 索引详情与健康状态使用现有 `IndexStatus` 和最近一次真实检索验证结果。

### 接口

- 新增 `GET /api/v1/admin/clauses/{clause_id}/references`。
- 返回真实引用总数、关联回答数、按问题聚合的引用次数、平均检索排名和最近引用时间。
- 无引用时返回零和空数组。

## 验收标准

- [ ] 四张统计卡可点击并正确定位或打开详情。
- [ ] 可按制度分类筛选现有制度列表。
- [ ] 制度名称、版本号、条款数和版本状态均可下钻。
- [ ] 可查看制度概览、版本历史、条款目录和完整条款原文。
- [ ] 条款引用只展示数据库中的真实问答引用；无数据时显示空状态。
- [ ] 预览、启停、删除、新增版本功能保持可用，删除确认不变。
- [ ] 索引发布和 Top 5 检索含义与交互不变。
- [ ] Drawer 可关闭，页面无横向溢出，键盘焦点可见。
- [ ] TypeScript strict、Vitest、Pytest和生产构建通过。

## 执行阶段

1. 复用现有数据增加前端下钻状态和 Drawer。
2. 增加条款引用只读聚合接口及类型。
3. 收纳低频危险操作并补齐测试。
4. 执行回归并重新部署网页。
