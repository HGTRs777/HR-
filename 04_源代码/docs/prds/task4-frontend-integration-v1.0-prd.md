# 任务 4 前端整合 - 产品需求文档 (PRD)

## 需求描述

### 背景

- **业务问题：** 任务 1–3 已完成工程、知识库和可信问答后端，但员工与 HR 页面仍为骨架，无法完成端到端操作。
- **目标用户：** 查询公司制度的员工，以及维护制度与检索索引的 HR 管理员。
- **价值主张：** 把已冻结 API 串成可演示、可验证、可管理的完整前端主链路。

### 功能概述

- 员工端：自然语言问答、多轮会话、会话历史、状态提示、逐声明证据引用、制度阅读器定位与高亮。
- HR 端：登录退出、制度上传/版本预览/启停/删除、索引状态与重建、Top 5 检索测试。
- 边界：只串接 F01–F11；F12–F15 的主动澄清、情景重放、一问一办和答案刷新保留现有占位，不在任务 4 伪造前端逻辑。
- 不包含：反馈闭环、数据洞察、真实 HRIS、审批和员工档案。

### 用户场景

1. 员工选择示例问题或输入中文问题，看到可信答案、拒答或降级提示。
2. 员工继续追问、切换历史会话，并点击证据跳转到正确制度版本和稳定锚点。
3. HR 登录后上传制度版本、预览解析条款、启停版本、重建索引并测试 Top 5。

## 设计决策

### 技术方案

- Vue 3 Composition API、TypeScript strict、Element Plus、Axios；不增加新的前端框架。
- API 访问集中在 `services/`，页面不自行拼装响应或判断证据有效性。
- `X-Client-Session-ID` 继续由 HTTP 客户端统一携带；管理员写操作使用会话 CSRF。
- 证据定位只使用 `stable_anchor` 作为 DOM 数据锚点，不使用数据库主键拼接 DOM ID。
- 桌面采用三栏员工工作台，窄屏降为单栏；HR 页面采用登录态控制和模块化卡片。

### 约束与异常

- 问题输入 1–1000 字，上传格式和 10 MB 约束由前后端共同提示、以后端校验为准。
- 所有 API 错误展示服务端安全消息；加载状态禁用重复提交。
- `answer/refusal/degraded` 使用明显但不依赖颜色单独表达的文本标签。
- 索引为 `stale/not_built` 时提示 HR 重建；未登录时不渲染管理数据。
