# 任务 5 创新工作流 - 产品需求文档 (PRD)

## 需求描述

### 背景

- **业务问题：** 可信问答已经能给出有证据的结论，但条件不足时仍可能直接回答，员工也无法修改条件比较结果、获得可执行清单或在制度更新后刷新答案。
- **目标用户：** 查询制度并需要完成具体事项的员工，以及维护制度口径的 HR。
- **价值主张：** 让回答从“可验证”进一步变为“先问清、可推演、能办理、会保鲜”。

### 功能概述

- **F12 主动澄清：** 对年假资格、请假审批和离职通知等条件敏感问题，缺少关键非敏感槽位时返回 `clarification`，不提前生成制度结论。
- **F13 情景推演：** 基于历史回答修改完整情景，重新检索和生成，返回前后条件变化；每次推演生成独立回答，保留历史证据。
- **F14 一问一办：** 只从已验证证据生成适用条件、时间线、材料和注意事项；每个步骤可回到证据原文。
- **F15 答案保鲜：** 通过知识指纹和引用版本判断过期；过期回答可按当前启用制度刷新，原回答不覆盖。
- **边界：** 仅使用 `employee_status`、`tenure_years`、`matter_type`、`duration_days`；不接入真实员工档案、审批流或法规知识。

### 输入、输出与交互

- 澄清选项提交后合并到当前情景并调用 `/chat/replay`；未知或敏感槽位继续拒绝。
- 推演必须携带原 `answer_id` 和更新后的完整情景；无实际变化时返回 400。
- `/chat/replay` 在 `meta` 返回 `previous_answer_id` 和逐字段变化摘要。
- 仅 `answer` 状态构造行动卡；卡片文本来自用户情景标签或证据原文，不允许无引用扩写。
- 仅过期回答显示刷新入口；刷新生成新回答，并在 `meta` 返回旧、新知识指纹。

## 设计决策

### 技术方案

- 继续使用 Vue 3、Flask、SQLAlchemy、SQLite 和现有混合检索/DeepSeek 可信生成管线。
- `Answer` 增加澄清快照、来源回答和生成方式，以支持历史回放与审计。
- 查询、推演、刷新复用同一可信生成函数；不复制检索或证据验证实现。
- 行动卡采用确定性证据抽取：含期限词的条款进入时间线，含申请/材料/凭证词的条款进入材料，含审批/限制词的条款进入注意事项。
- 前端按服务端返回渲染澄清按钮、情景沙盘、差异提示、行动卡和刷新状态。

### 约束与风险

- 制度不足、索引过期、模型异常继续沿用拒答或降级规则。
- 澄清规则只覆盖制度样本中确实影响结论的条件，避免对所有问题强制提问。
- 推演与刷新不修改旧回答，保证历史证据快照可审计。
- 行动卡步骤必须携带有效 `evidence_ids`，前端点击后复用稳定锚点阅读器。
