# 任务 7 统一集成、测试与交付 - 产品需求文档 (PRD)

## 需求描述

### 背景

- **业务问题：** 任务 1–6 已分别完成 F01–F18，但模块通过不等于项目具备可重复启动、可审计验收和可移交使用的完整交付形态。
- **目标用户：** 课程验收人员、项目演示人员、后续维护开发者，以及使用员工端和 HR 管理端的演示用户。
- **价值主张：** 将现有模块统一成可初始化、可启动、可测试、可演示、可追踪的最终项目交付包。

### 功能概述

- 串联员工问答、HR 知识维护、答案保鲜、意见闭环与数据洞察。
- 核验 Flask 实际 JSON、API 契约和 TypeScript 类型的一致性。
- 审核 Alembic 迁移链，清理确属重复或临时的迁移，不压缩合法历史。
- 完成后端、前端、端到端、安全与异常场景回归。
- 提供传统前后端分离运行的一键启动/停止脚本、配置说明、用户手册与测试报告。
- 更新 F01–F18 追踪矩阵，为每项需求给出接口、页面与测试证据。
- **不包括：** 新增 F19、生产云部署、真实员工数据、通用 BI、复杂企业权限和外部通知。

### 详细需求

- Windows PowerShell 一键脚本分别启动 Waitress 后端和 Vite Preview 前端，执行数据库迁移及健康检查；失败时给出明确错误并避免假成功。
- 交付配置只提交 `.env.example`，不提交密钥、真实密码、SQLite 运行库、上传文件、模型缓存或构建产物。
- 自动化覆盖正常流程以及伪造证据、非法模型 JSON、模型超时、索引过期、重复版本、恶意/不支持文件和并发重建。
- 以正式需求报告中的 12 个验收场景为基线，补充 F18 指标与过滤验收。
- 最终测试报告记录命令、环境、结果、已知限制和人工浏览器证据。

## 设计决策

### 技术方案

- 保持 Vue 3 + Vite 与 Flask + SQLAlchemy + SQLite 分开运行，不将前端产物交给 Flask 托管。
- 后端正式演示由 Waitress 运行于 `127.0.0.1:5000`；前端生产构建由 Vite Preview 运行于 `127.0.0.1:5173`。
- 一键脚本只编排既有 CLI、迁移、构建和服务，不复制业务逻辑。
- 契约核验以 `docs/api-contract.md`、实际 API 序列化器和 `frontend/src/types/api.ts` 三方比对为准。
- 迁移保留线性、可升级的历史；仅删除确认未使用且重复的临时修订。

### 约束条件

- Windows PowerShell 5.1+；Python 与 Node.js 版本沿用现有项目依赖要求。
- 启动脚本不得写入或回显 DeepSeek 密钥。
- DeepSeek 不可用时系统必须保持本地证据降级演示能力。
- 自动测试不得发起真实模型请求。

### 风险评估

- BGE 首次下载可能受网络影响；配置说明必须说明缓存和首次构建行为。
- 端口占用可能导致启动失败；脚本须在启动前检查 5000/5173。
- 真实模型结果不完全确定；终验核心以确定性测试和本地证据降级为准，在线冒烟单独记录。
