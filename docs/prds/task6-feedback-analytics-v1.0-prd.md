# 任务 6 反馈闭环与数据洞察 - 产品需求文档 (PRD)

## 需求描述

### 背景

- **业务问题：** F01–F15 已形成可信问答与创新办理链路，但员工无法把错误、缺失或建议提交给 HR，HR 也缺少处理、复测和趋势分析工具。
- **目标用户：** 提交制度意见并跟踪结果的员工，以及治理制度知识质量的 HR 管理员。
- **价值主张：** 将单次问答升级为可追踪、可复测、可沉淀的知识共创闭环。

### 功能概述

- **F16 共创意见箱：** 员工针对自己的回答提交匿名或实名意见，查看本人会话下的意见及处理时间线。
- **F17 反馈闭环：** HR 筛选意见，按合法状态流处理，使用原问题/情景/证据执行检索复测，并将通过且已解决的意见固化为回归用例。
- **F18 数据洞察：** HR 查看查询量、命中/拒答/澄清/降级率、平均耗时、热门问题、未命中问题及反馈分类/状态。
- **边界：** 不发送邮件或短信，不接入 HRIS，不记录真实员工档案，不提供绩效监控。

### 详细需求

- 反馈类型固定为回答错误、制度缺失、制度过期、表述不清和改进建议；内容 1–1000 字。
- 匿名反馈忽略姓名；实名反馈要求 1–80 字姓名。
- 服务端根据 `answer_id` 复制问题、情景、声明、证据、版本和知识指纹，拒绝前端提交快照。
- 状态流为 `open → processing → resolved`，以及 `open/processing → rejected`；允许 `processing → open` 退回。
- 每次提交、状态变化、复测和回归固化都新增 FeedbackEvent，不修改历史事件。
- 复测比较当前 Top 5 稳定锚点与原回答证据；全部原证据仍被召回才通过。
- 只有已解决且最近复测通过的反馈可固化，且同一反馈只生成一个回归用例。
- 洞察支持日期、制度和反馈状态过滤；比例分母为过滤后的查询量。

## 设计决策

### 技术方案

- 延续 Flask、SQLAlchemy、SQLite、Vue 3 和 Element Plus。
- Feedback 增加匿名客户端归属、回答快照和主制度 ID，确保回答/会话删除后意见仍可追踪。
- 复测复用现有混合检索，不调用模型，不向员工会话写入新消息。
- Analytics 从 QueryLog、Feedback 和 Policy 聚合，不增加外部分析服务。
- 前端 API 分为员工 `feedback.ts` 与 HR `admin.ts`，所有管理写操作沿用 Session + CSRF。

### 风险与约束

- 员工只能访问当前 `X-Client-Session-ID` 的意见；管理员接口统一鉴权。
- 反馈快照不可由 PATCH 修改，避免事后覆盖证据。
- 空日志时所有比例返回 0，排行榜返回空数组。
- SQLite 数据量定位为课程项目和部门级演示；排行榜默认 Top 10。

- [x] 员工可匿名/实名提交意见，且匿名记录不保存姓名。
- [x] 反馈自动复制回答、声明、证据、版本和情景快照，并执行会话隔离。
- [x] HR 可筛选并按合法状态流处理，非法跳转返回 409。
- [x] 每次操作新增不可覆盖事件，员工可查看处理时间线。
- [x] HR 可复测原问题；通过且已解决后可固化唯一回归用例。
